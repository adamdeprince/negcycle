Overview

Built for repeated market updates, not one-off graph demos

NegCycle models rates as a directed graph and searches for the most profitable simple cycle under a configurable maximum cycle length. Internally it operates on transformed edge weights and returns exact cycle candidates rather than approximate graph trivia.

The project is aimed at the workflow where books and quotes keep changing and you want to update one detector object repeatedly instead of rebuilding the world on every tick.

What It Optimizes

  • Exact simple-cycle search
  • Incremental single-edge updates
  • Incremental two-leg book updates
  • Backend-specific scalar and SIMD paths

Backends

Eleven architecture backends from one Python import

detect_best_backend() resolves an architecture-specific native implementation behind the same top-level API. A generic scalar implementation remains the fallback. On x86, AVX-512 is selected whenever it is compiled and supported, with AVX2 next in line.

  • x86 SSE, AVX, AVX2, and AVX-512
  • aarch64 ASIMD and SVE
  • macOS ARM64 NEON
  • LoongArch LSX and LASX
  • RISC-V RVV
  • POWER VSX
from negcycle import ArbitrageDetector

# Resolved dynamically from the CPU-specific backend modules.
detector = ArbitrageDetector()

Native Surface

Shared types, specialized compute

The Python-visible Edge and Cycle types live in a shared native module, while the detector implementation is bound separately per backend. Shared support logic stays in the common base; vector-specific hot paths stay specialized.

Limits

Where it doesn't win

  • AVX-512 does not materially separate from AVX2 on the smallest hot update paths: 0.641 vs 0.647 µs for two-leg updates and 0.445 vs 0.441 µs for single-leg updates. Those roughly 1% gaps are noise.
  • On Loongson, LASX measures 0.88× against generic for the quote-best workload because SIMD mask and update overhead dominate at that size.

Quick Start

Basic Python usage

from negcycle import ArbitrageDetector

detector = ArbitrageDetector()

detector.add_quote("USD", "EUR", executable_rate=0.92, fee_bps=2)
detector.add_quote("EUR", "BTC", executable_rate=0.000015, fee_bps=2)
detector.add_quote("BTC", "USD", executable_rate=73_000, fee_bps=2)

cycle = detector.find_best_arbitrage(max_cycle_length=3)

if cycle is not None:
    print(cycle.gain_factor)
    for edge in cycle.edges:
        print(edge.from_currency, edge.to_currency, edge.net_rate)

Incremental API

Update one quote and ask again

NegCycle is designed for warm detectors. If one edge changes, use the incremental methods instead of throwing away the whole state. 

cycle = detector.add_quote_and_find_best_arbitrage(
    "BTC",
    "USD",
    executable_rate=103_400,
    fee_bps=4,
    max_cycle_length=3,
)

Book Updates

Two-leg book updates are first-class

If you work in bid/ask space instead of precomputed directed quotes, the detector can update both directions implied by a book and return a new best cycle in one step. 

cycle = detector.add_book_and_find_best_arbitrage(
    "ETH",
    "USD",
    bid=3540,
    ask=3545,
    fee_bps=4,
    max_cycle_length=3,
)

Build

Build through Poetry or directly without isolation

The project uses scikit-build-core, nanobind, CMake, and Ninja. If you are offline or debugging native build issues, use the project environment directly instead of relying on isolated backend dependency downloads. 

poetry install --with dev
poetry run pip install --no-build-isolation -ve .
poetry install --with dev
bash scripts/build-wheel-no-isolation.sh

Repo Layout

Files that matter first

  • src/negcycle/__init__.py for Python import routing
  • src/cpp/module.cpp for backend exposure
  • src/cpp/common/ for shared detector logic and bindings
  • src/cpp/backends/ for backend-specific hot paths
  • CMakeLists.txt for native target wiring
  • scripts/build_docs.py for the static documentation build

Scope

What this project is not

NegCycle is not a full execution stack, venue adapter layer, or order management system. It is a fast arbitrage-cycle engine with a Python surface and native backends you can benchmark and extend.
